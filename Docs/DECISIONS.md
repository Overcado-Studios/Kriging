# Decisions and gate outcomes

## D001 — contract to one core module

The reviewed snapshot declared four modules while omitting every `Build.cs` and one module's source. The corrected manifest declares only `KrigingCore`, for which the module rules and entry point are present. Known-broken editor, renderer, PCG, shader, content, and legacy trees are not shipped as inactive-looking source inside the plugin.

## D002 — one production numerical path

`KrigePortableCore.cpp` is both the Unreal module's implementation and the standalone gate's implementation. Tests do not exercise a rewritten Python or second C++ facsimile while leaving the shipped path untouched.

## D003 — internal partial-pivot LU for the portable gate

Eigen availability is an Unreal M0 gate and cannot be resolved without each target engine installation. The active gate uses the internal pivoted LU on every platform. A future Eigen path must remain cross-checked against it and must not create engine-version-dependent numerical conventions.

## D004 — analytic CPU variograms

The previous lookup design first paid a fifth-root per evaluation and was then replaced by an oversized dyadic table whose evidence never called the C++ lookup. The correctness gate removes the lookup entirely. Performance lookup design may return only after direct benchmarks and production-path parity tests exist.

## D005 — zero ridge first

A fixed ridge makes an exactness property self-contradictory. The core first factorizes with zero ridge, then escalates only after failure. The applied ridge is reported. Fast LOO is disabled whenever ridge is nonzero.

## D006 — runtime-checked fast LOO

For eligible models at 60 samples or fewer, the inverse-diagonal result is compared with complete rebuilds in the same call. A mismatch returns brute force rather than a confident fast report. Above 60, the report explicitly remains unverified against the per-model reference.

## D007 — no tiled variance

A smoothstep average of variances from different neighborhood systems is not the variance of the blended estimate. Tiled blending and tiled variance are absent until a derivation and parity test exist.

## D008 — no active GPU path

The inherited GPU evaluator was unreachable from production code and had never compiled. A nominal self-test does not remediate an unreachable subsystem. Renderer code and shaders are absent from this gate. They may return only after packaged shader mapping and a real CPU/GPU parity matrix pass.

## D009 — no Cesium public surface

Cesium was inherited from the zero-shot draft but is outside the original scope. The corrected package removes it rather than promoting it to a public API before M0. A future optional integration must be a separate module and must not alter the core coordinate convention.

## D010 — bounded synchronous references

Brute-force LOO is a reference implementation, not an editor feature for arbitrary `n`. It is capped at 60 samples. Larger calls fail with a descriptive message rather than starting unbounded synchronous O(n^4) work.
